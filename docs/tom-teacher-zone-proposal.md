# Tom 老师专区方案提案

状态：待审核。本提案只定义设计方向，不包含页面、接口或存储资源的实现。

## 目标

在首页“创作参考”区域增加 Tom 老师专区入口，公开展示 Tom 老师持续更新的作品、提示词和相关图片/视频。Tom 老师每天可以提交新内容；内容发布后，访客无需登录即可浏览。

## 推荐方案

保留前台静态站点和现有数据发布模式：

- 图片、视频文件存放在 Cloudflare R2，并通过专用媒体域名公开读取。
- 作品标题、提示词、简介、标签、封面地址和媒体地址保存在仓库的 `data/tom-teacher.json`。
- 前台专区读取这个 JSON 并渲染作品；首版不新增用户上传 API、数据库或站内管理后台。
- Tom 老师将媒体上传到 R2，再通过 GitHub 提交内容清单变更。变更经审核合并后发布。
- 合并主分支后自动部署 Cloudflare Pages。当前项目说明记录的是手动发布，因此实施时需要配置并验证 Pages 自动部署，避免每天依赖人工发布。

此方案把大体积二进制媒体留在 Git 仓库之外，同时让内容清单可审查、可回滚，并沿用静态站点前台。

## 内容更新流程

1. Tom 老师将图片或视频上传到 R2 指定目录，使用不重复的文件名或内容 ID。
2. 在 `data/tom-teacher.json` 新增作品记录，填写媒体 URL、标题、提示词及其他展示信息。
3. 提交 GitHub Pull Request；PR 预览用于检查文案、媒体链接和页面显示。
4. 合并后由 Cloudflare Pages 自动发布。

Tom 老师需要具备 R2 上传权限和 GitHub 仓库写入权限。首版不提供网页表单上传；如果后续需要不经过 GitHub 的自助发布，再单独设计受认证保护的管理后台。

## 建议的数据结构

```json
{
  "id": "tom-2026-11-04-001",
  "title": "作品标题",
  "description": "作品简介",
  "prompt": "可复制的提示词",
  "cover": "https://media.dazi.studio/tom/2026/11/04/cover.webp",
  "media": [
    {
      "type": "image",
      "url": "https://media.dazi.studio/tom/2026/11/04/image.webp",
      "alt": "图片说明"
    }
  ],
  "tags": ["人像", "光影"],
  "publishedAt": "2026-11-04T08:00:00+08:00"
}
```

数据校验至少应检查必填字段、唯一 ID、媒体类型、允许的媒体域名，以及标题和 URL 的格式。草稿不进入公开 JSON；首版可通过 PR 审核控制发布。

## 页面范围

- 在首页参考区增加 Tom 老师专区入口，保持现有卡片样式和中英文切换。
- 专区展示作品列表，支持打开详情、查看图片/播放视频、复制提示词。
- 详情页或弹窗需在手机端可用；列表采用分页或按需加载，避免一次加载全部媒体。
- 媒体使用 R2 URL 外链加载，不把图片和视频复制进 Git 仓库。

## 发布和运维要求

- 创建独立的 R2 bucket 或清晰隔离的 `tom/` 前缀，并绑定媒体域名。
- R2 写权限仅授予维护者；公开网站只需要读取媒体。
- 对上传格式、单文件大小、文件名和总容量制定限制；大视频的播放兼容性与转码需求在实施前验证。
- 媒体 URL 使用版本化或不可变文件名，避免 CDN 缓存让替换文件后仍展示旧内容。
- GitHub Actions 校验 JSON 和媒体域名；PR 提供 Pages 预览。合并主分支后部署生产站点。
- 明确内容撤下流程：从清单移除记录，并按保留策略删除或归档 R2 对象。

## 不在首版范围

- 站内上传后台、Tom 老师账号系统、草稿编辑器和定时发布。
- 用户评论、点赞或其他互动功能。
- 图片/视频生成、转码流水线和第三方生成 API。
- 将作品媒体存进 Git 或 Git LFS。

## 实施前待确认

- Tom 老师是否接受通过 R2 控制台上传媒体、通过 GitHub PR 提交作品信息。
- 首版是否同时支持图片与视频，以及单个作品允许的媒体数量和大小。
- 专区详情采用独立页面还是首页弹窗。
- Cloudflare Pages 当前项目是否可配置 GitHub Actions 自动部署及 PR 预览；确认所需凭据和权限后再实施。

## 实施顺序

1. 确认内容字段、媒体限制和专区展示形式。
2. 配置 R2 bucket 与媒体域名，并验证公开读取和访问控制。
3. 加入 JSON 校验与 Pages 预览/自动部署流程。
4. 实现专区入口、列表和详情交互。
5. 发布少量样例内容，核对桌面端、移动端、缓存和视频播放后再正式开放更新。
